# One Workbench, one execution history

The sidebar opens Home, Active Work, Apps, Brain, Automations and Artifacts. The selected section is retained in the URL across reload; browser Back/Forward returns to the same section. Job, Attempt, run and session selection remain separate from navigation. Changing sections never starts work or grants approval.

## From context to work

Use Brain to review the current repository/workspace context, then open Home for a task. Context selection is bounded and non-authoritative. Where recorded, Active Work details show the exact selected entry versions. A preview does not prove past use. A saved scripted workflow uses its reviewed input verbatim: learned preferences do not silently change approved action fields.

## From an account to a workflow

Apps shows connection health and actual available actions. Review the exact account, action and inputs before saving a workflow. Open workflow runs and history to reach Automations. Saving or opening a workflow is not action approval. Run or schedule through the existing Automation authority, answer any exact-action approval in Workbench, then inspect the child Job, Evidence, Verification and cleanup in its history. Unknown or interrupted execution remains unknown until canonical reconciliation; a browser success message is not proof of an external effect.

## Test Lab and Core

The separately installed private Test Lab beta uses this same local Core. Its report links open the exact session, Job, Attempt and run in Workbench for approvals, Evidence and Proof. Its agreed site/environment and Core workspace remain part of the approved check. A mismatch is rejected, not silently relinked.

Test Lab is not included in the public Core package. It currently has its own founder-operated beta interface and supported local startup procedure; Core does not advertise an unverified one-click private-product launch. The four accepted browser-flow families do not imply support for native Windows checks, automated sign-in, redirects or unrestricted browsing.

## Honest readiness

Connection health, execution readiness and final Verification are different states. A configured connector still needs an authorized account and supported action scopes. A model/provider may be unavailable even when local Workbench is healthy. Setup errors remain visible and must not be bypassed by navigation. Current installer limitations and real-provider acceptance requirements are recorded separately from builder test results.
